# Milestone v1.0: Test Infrastructure & Service Cleanup

**Status:** ✅ SHIPPED 2026-01-17
**Phases:** 1-3
**Total Plans:** 7 (03-03 skipped)

## Overview

This milestone focused on establishing a robust test suite and improving codebase quality. The journey started with test infrastructure and E2E test patterns, then used that safety net to refactor debugging systems, clean up service layers, and improve code organization. The goal was velocity through confidence: move faster knowing core functionality won't break.

## Phases

### Phase 1: Test Infrastructure & Baseline

**Goal**: Establish XCTest framework with async/await support and E2E test patterns for video processing pipeline
**Depends on**: Nothing (first phase)
**Plans**: 3 plans

Plans:

- [x] 01-01: Test Evaluation Infrastructure - IoU-based fuzzy matching, test resource loaders, and comprehensive documentation
- [x] 01-02: E2E Test Implementation - Shot detection test with async/await pattern and helpful error messages
- [x] 01-03: Test Plan Organization - Smoke and Regression test plans for development workflow

**Details:**

Created comprehensive test infrastructure with:
- SegmentEvaluator utility for IoU-based fuzzy matching (0.5 threshold default)
- TestResourceLoader for loading test videos and ground truth JSON
- GroundTruth data models (Codable)
- E2E test pattern: load resources → process video → fuzzy evaluation → output metrics → assert
- Smoke test plan (5 min timeout) for quick development feedback
- Regression test plan (30 min timeout) with code coverage for comprehensive pre-commit validation

**Key Decisions:**
- IoU threshold default: 0.5 (standard for object detection, tunable per-test)
- FP/FN guardrails: <15% FP, <10% FN (stricter on FN - missing segments worse than extra)
- Ground truth format: JSON (human-readable, Codable)
- Use real VideoProcessingService for E2E tests (validates full pipeline vs mocking)

### Phase 2: Core E2E Test Coverage

**Goal**: Build tests for export flows, UI navigation, and error handling paths
**Depends on**: Phase 1
**Plans**: 2 plans

Plans:

- [x] 02-01: Accessibility Infrastructure - Shared AccessibilityIdentifiers.swift with screen object pattern
- [x] 02-02: E2E Test Implementation - Tests for creation flow and export flow using semantic element discovery

**Details:**

Built E2E test infrastructure with:
- Single-source-of-truth AccessibilityIdentifiers.swift with nested enums (Home, Creation, Project, Export)
- Symlinked constants to UITests target to avoid duplication
- AppScreen protocol with screen objects (HomeScreen, HighlightCreationScreen, etc.)
- XCTestCase extensions for waitForHittable/waitForDisappear
- HighlightCreationFlowTests: 4 test methods for flow entry, close, and sport selection
- ExportFlowTests: 4 test methods for project sheet, export button, and export options
- NSPredicate-based dynamic element discovery (not fragile coordinate-based lookups)

**Key Decisions:**
- Symlink AccessibilityIdentifiers.swift instead of duplicating (single source of truth)
- Screen object pattern with typed properties for semantic element access

### Phase 3: Service Layer + UI Cleanup

**Goal**: Refactor service protocols, implementations and UI for clarity and separation of concerns
**Depends on**: Phase 2
**Plans**: 4 plans (03-03 skipped)

Plans:

- [x] 03-01: Extract ProcessingReportManager - Separated debug report orchestration from VideoProcessingService
- [x] 03-02: Extract ThumbnailService - Created injectable service for thumbnail generation with protocol + mock
- [ ] 03-03: CompletedProjectSheet ViewModel extraction - SKIPPED (deferred, can be done later)
- [x] 03-04: Extract VideoLoaderService - Moved video loading strategies out of HighlightCreationViewModel + background loading

**Details:**

Service layer refactoring with test safety net:
- ProcessingReportManager: Actor-based thread-safe debug report operations (VideoProcessingService 884→675 lines, -24%)
- Optional dependency injection pattern for conditional features (nil manager = no debug reporting)
- ThumbnailService: Protocol + RealImpl + MockImpl pattern (BackgroundProcessingManager 238→212 lines)
- VideoLoaderService: Extracted PHAssetResourceManager → PHImageManager → Transferable fallback chain
- **Background video loading**: Creation flow now dismisses immediately, video loads in BackgroundProcessingManager (HighlightCreationFlow 767→487 lines, -36%)
- Slow-mo videos no longer block UI during loading

**Key Decisions:**
- Actor-based ProcessingReportManager for thread safety
- Optional dependency injection for backward compatibility
- Default parameter pattern for service injection (backward compatible without changing call sites)
- Move video loading to background processing (immediate UI dismissal, better UX)
