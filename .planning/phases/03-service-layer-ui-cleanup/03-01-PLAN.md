Create a new ProcessingReportManager class that handles debug report orchestration:

1. Create protocol `ProcessingReportManagerProtocol` with methods:
   - `startReport(for project: Project, sourceURL: URL, sport: Sport, sportMode: SportMode?) -> DebugReportBuilder`
   - `recordAudioAnalysis(_ result: AudioAnalysisResult, to builder: inout DebugReportBuilder)`
   - `recordVisualValidation(_ result: VisualValidationResult, to builder: inout DebugReportBuilder)`
   - `recordExport(_ result: ExportResult, to builder: inout DebugReportBuilder)`
   - `finalizeReport(_ builder: DebugReportBuilder) async throws`

2. Create `RealProcessingReportManager` implementation that:
   - Takes `DebugReportService` as dependency (injected, not created)
   - Implements all protocol methods by delegating to DebugReportService
   - Handles timing calculations for report sections
   - Keeps the complex debug data structuring logic

3. Use `// MARK:` comments to organize sections

Follow existing conventions:
- Protocol in same file as implementation
- camelCase functions, PascalCase types
- Use `async throws` for methods that can fail
