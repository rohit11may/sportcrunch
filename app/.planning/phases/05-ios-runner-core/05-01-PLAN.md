<task type="checkpoint:human-action" gate="blocking">
  <name>Task 1: Create SportCrunchRunner target in Xcode</name>
  <action>
    User must manually create the new target in Xcode:
    1. Open SportCrunch.xcodeproj in Xcode
    2. File > New > Target
    3. Choose "App" under iOS
    4. Product Name: SportCrunchRunner
    5. Bundle Identifier: (your team's bundle ID prefix).SportCrunchRunner
    6. Language: Swift
    7. User Interface: SwiftUI
    8. Uncheck "Include Tests"
    9. Click Finish
    10. Add Swifter SPM dependency:
        - File > Add Package Dependencies
        - Enter: https://github.com/httpswift/swifter
        - Add to target: SportCrunchRunner
    11. Link SportCrunch framework to SportCrunchRunner:
        - Select SportCrunchRunner target
        - Build Phases > Link Binary With Libraries
        - Add SportCrunch (the main app framework)
        - OR: Simply add the source files to SportCrunchRunner target membership
  </action>
  <resume-signal>Type "target created" when the SportCrunchRunner target exists with Swifter dependency</resume-signal>
</task>

<task type="auto">
  <name>Task 2: Create HTTPServer wrapper</name>
  <files>SportCrunchRunner/Server/HTTPServer.swift</files>
  <action>
    Create an HTTPServer class that wraps Swifter's HttpServer:

    - Import Swifter
    - Class HTTPServer with:
      - Private HttpServer instance
      - Configurable port (default 8080, read from UserDefaults or environment)
      - start() method that calls server.start() on specified port
      - stop() method for cleanup
      - Method to register route handlers: registerRoute(path:method:handler:)
      - Published property for server state (running, stopped, error)
    - Use @MainActor for state properties
    - Log server URL (IP:port) on successful start
    - Get device IP using getifaddrs() to display connectable address

    Pattern: Keep it simple - this is a dev tool, not production server.
  </action>
  <verify>File exists at SportCrunchRunner/Server/HTTPServer.swift, compiles without errors</verify>
  <done>HTTPServer class can start Swifter on configurable port with route registration capability</done>
</task>

<task type="auto">
  <name>Task 3: Create health endpoint and wire server startup</name>
  <files>SportCrunchRunner/Server/HealthEndpoint.swift, SportCrunchRunner/RunnerApp.swift</files>
  <action>
    Create HealthEndpoint.swift:
    - Function registerHealthEndpoint(on server: HTTPServer)
    - Registers GET /health route
    - Returns JSON: {"status": "ready", "timestamp": ISO8601 date}
    - Use JSONEncoder for response

    Update RunnerApp.swift (created by Xcode):
    - Import the server module
    - Create HTTPServer instance as @StateObject
    - Call server.start() in .onAppear or init
    - Register health endpoint before starting
    - Display basic "Runner Starting..." text in body (UI comes in Plan 03)

    Note: If Xcode created ContentView.swift, you can either use that or replace RunnerApp body directly. Keep it minimal.
  </action>
